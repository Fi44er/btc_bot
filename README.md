# ₿ BTC Bot

Telegram-бот для приёма Bitcoin-платежей с автоматическим зачислением баланса в рублях и последующим выводом на банковскую карту.

---

## 🎯 Задача проекта

Бот решает задачу **удобного приёма BTC-платежей** для пользователей, которым нужно получить рубли на карту:

1. Пользователь указывает номер банковской карты.
2. Получает уникальный Bitcoin-адрес для пополнения.
3. Отправляет BTC на этот адрес.
4. Бот автоматически отслеживает транзакцию, конвертирует BTC → RUB по актуальному курсу и зачисляет сумму на внутренний баланс.
5. Администратор получает уведомление о пополнении и связывается с пользователем.
6. После перевода денег на карту пользователь подтверждает получение — баланс корректируется.

Это позволяет принимать криптовалюту и выдавать фиат без необходимости вручную отслеживать каждую транзакцию.

## 🚀 Запуск локально

### Требования

- Go 1.23+
- Docker & Docker Compose (рекомендуется)
- Telegram Bot Token ([@BotFather](https://t.me/BotFather))
- Master Key Seed (xprv / HD seed для генерации адресов)

### 1. Клонирование и конфигурация

```bash
git clone <repo-url>
cd btc_bot

cp example.env .env
```

Отредактируйте `.env`:

```env
TELEGRAM_BOT_TOKEN="123456:ABC-DEF..."
ADMIN_CHAT_ID=987654321
MASTER_KEY_SEED="xprv9s21ZrQH143K..."
DB_URL="postgres://root:root@localhost:5432/btc"
```

### 2. Запуск через Docker Compose

```bash
docker-compose up -d --build
```

Это поднимет:
- PostgreSQL на `localhost:5432`
- Backend-бот (network_mode: host)

### 3. Запуск без Docker

```bash
# Поднять PostgreSQL отдельно
docker run -d --name postgres \
  -e POSTGRES_USER=root \
  -e POSTGRES_PASSWORD=root \
  -e POSTGRES_DB=btc \
  -p 5432:5432 postgres:alpine

# Установить зависимости и запустить
go mod download
go run ./cmd/bot
```

Миграции выполняются автоматически при старте.

## ⚠️ Обработанные ошибки и edge cases

| Ситуация | Поведение |
|----------|-----------|
| Пользователь без карты запрашивает адрес | Отказ с просьбой сначала указать карту |
| Пользователь уже имеет кошелёк | Возвращается существующий адрес, новый не генерируется |
| Дублирующая транзакция (тот же TXID) | Игнорируется, баланс не начисляется повторно |
| Неподтверждённая транзакция | Сохраняется, но баланс не обновляется до `confirmed = true` |
| Ошибка получения курса BTC/RUB | Используется fallback-курс (~3.9–4 млн RUB) |
| Неверный ввод суммы при подтверждении вывода | Операция отменяется, баланс не меняется |
| Сумма к списанию больше баланса | Отказ с детализацией (баланс / требуется) |
| Баланс ≤ 0 при запросе вывода | Сообщение «нет средств для вывода» |
| Ошибка API mempool.space | Логируется, проверка пропускается для пользователя |
| Неизвестный пользователь | Автоматически создаётся при первом сообщении |
| Callback от не-админа | Отклоняется |
| Некорректные данные callback | Логируется ошибка, пользователю показывается сообщение |
| Panic при создании кошелька | Транзакция БД откатывается (defer + recover) |
| Невалидный статус вывода | Валидация: только `pending` / `completed` / `canceled` |

### Формула списания при подтверждении вывода

```
amountToDeduct = (receivedAmount / 1.11) * 1.06
```

Это учитывает комиссию/спред при обмене.

## 🔒 Безопасность

- Приватные ключи адресов хранятся в БД (поле `PrivateKey`).
- Master seed задаётся через переменную окружения и **не** должен попадать в git.
- Админские действия доступны только `ADMIN_CHAT_ID`.
- Рекомендуется использовать отдельные seed-фразы для production и не хранить большие суммы на адресах бота.
